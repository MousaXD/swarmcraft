# Agent 01 — signed V2 migration quorum admission (2026-11-20)

**Status: partial, inert consensus prerequisite. NOT live V2 authority admission.**

Implementation is isolated to `swarm-consensus::v2_migration_quorum`, the consensus crate's Ed25519 dependency, the session-bound V2 action verifier in `swarm-network::authority_capability`, and a new bounded verifier-owned challenge book in `swarm-network::v2_challenge_book`. It is based on the existing signed V2 protocol types from Agent 02 and the inert negative gates from Agent 11. V1 authority/lease, wire, persistence and Minecraft launch paths are intentionally unchanged.

## Verified checks

- The distinct V2 realm proposal must extend explicit independently pinned accepted V1 world/config/membership/snapshot/epoch/fencing values. The proposed identity must not equal the source world.
- The source canonical membership, initial V2 realm-hosting policy and migration proposal must have valid Ed25519 signatures by the active canonical source authority. The initial policy must be sequence 1, have no predecessor, and match the proposed realm and exact migration policy hash. Source member key identities, sorted membership and non-banned authority eligibility are checked.
- Each migration vote must be a valid domain-separated signed V2 vote from an unbanned canonical member, with the exact proposal hash and accepted source membership hash. Unknown, mismatched, duplicated, mutated and insufficient votes fail closed.
- Quorum counts **all active V1 voters**, including player-only and storage-only members, not only authority-eligible hosting candidates.
- A pending old/new membership transition is explicitly blocked until an independently certified joint quorum can be checked. No silent reduction of the voter universe.
- Stale source hashes, snapshots, epochs, invalid target fencing, corrupted membership signatures, substituted/unsigned initial policies, and forged proposals fail closed.
- Verifier-owned V2 authority challenges use OS cryptographic randomness, a bounded 1,024-entry registry, one live challenge per authenticated local connection generation + realm, 30-second monotonic expiry and single-use consumption **after** signature verification. Any reconnect, policy, membership, fencing or consent update must invalidate outstanding challenges. `verify_registered_v2_session` constructs the canonical expected scope from local, independently obtained trusted fields, not remote claims. No challenge survives a process crash.
- Verifier-owned **V2 authority action nonces** are separately issued after signed session verification, bound to the exact signed action operation, expected signer, canonical realm/policy/migration/membership/snapshot, candidate, epoch/fence, heap, consent revision, and local connection generation. The one-use action nonce is passed into the existing signed action verifier and consumed only after valid Ed25519 signature verification. The registry allows only one unresolved action per realm at a time, refusing concurrent transfer/recovery or two-successor attempts. It is bounded to 1,024 realms with 30-second monotonic expiry and mandatory revoke/reconnect invalidation. **Local serialization does not prevent distributed simultaneous successors; durable canonical root CAS, quorum and fencing remain mandatory.**
- A fresh cryptographically verified `VerifiedAuthorityFeatureSession` must bind a signed V2 action to the exact target realm, candidate, committed policy/migration/membership/snapshot, epoch, fencing, consent revision and selected heap. Action kind, expected signer and unpredictable nonce must match trusted expectations. An action nonce must be atomically consumed once after signature verification, with the exact signed 32-byte nonce passed to the verifier-owned replay consumer (not an arbitrary caller-captured value). Expired sessions, tampered actions, policy mismatch, revoked/stale revision and replay are rejected. This remains proof binding only.

## Non-negotiable missing dependencies

1. **Trusted source history** — the caller of the quorum checker must obtain accepted V1 history pins from independently verified canonical storage, validate the full signed V1 history and latest snapshot/epoch, prove the absence of an outstanding pending membership transition, and check the current accepted authority fence/lease. A caller cannot mint trustworthy pins by copying fields from a remote proposal.
2. **Joint consensus** — verify pending old/new voter-set transition certificates and require both authentic majorities where a change is pending. The current stable-voter verifier returns an error instead.
3. **Canonical durable activation** — implement atomic compare-and-swap of the uniquely accepted V2 realm and immutable accepted roots, crash-safe replay detection, conflicting successor prevention, policy chain and rollback/downgrade rejection. `VerifiedV2MigrationVoteSet` has no conversion to an active policy/authority state.
4. **Network isolation** — negotiate a genuinely distinct `/swarmcraft/hosting-authority/2` transport with challenge bound to the live connection and source-validated committed migration hash. The legacy `/swarmcraft/1` transport, V1 PeerHello strings or replication/membership must never authorize V2 authority. Agent 11 owns protocol representation.
5. **Runtime routes and resource admission** — integrate the durable accepted-root policy, separate V2 transport, verifier-owned session/action challenge books and signed action/session verification into *every* direct launch, recovery, transfer, wake, lease grant, and renewal path. The current challenge books are not yet attached to the live libp2p node's connection lifecycle, so their standalone tests must not be confused with production enforcement. Agent 03 owns atomic local consent and resource budget proofs; only current verified local runtime state can prove heap/headroom.
6. **Independent certification** — exact-head Required Validation + Main Desktop Installers, adversarial mixed-version/partition/crash and three real machines, Agent 07 independent review and Agent 00 merge governance.

## Security disposition

Do **not** activate V2, merge into main, close #84 or treat this vote-set predicate as a certificate of canonical migration. The old V1 quorum/fencing rules remain authoritative for existing V1 worlds. If the source history cannot be independently certified and legacy authorities cannot be excluded, V2 hosting must remain fail-closed.
